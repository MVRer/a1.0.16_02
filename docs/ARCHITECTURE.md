Contracts and ownership. Every worker reads this file and then only the DESIGN.md sections named in its prompt. The orchestrator is the only one who changes `core`. If you need something here changed, say so in your report. Javadoc on the `core` classes is the detailed reference.

## Build
- MC 26.3, Java 25, Loom 1.18-SNAPSHOT, loader 0.19.5, Fabric API 0.162.0+26.3. These come from the official template. Do not change them.
- The Gradle daemon runs on JDK 25 (`gradle/gradle-daemon-jvm.properties`, Homebrew `openjdk@25`).
- Build: `./gradlew build`. It also runs the game tests (`check` depends on `runGameTest`).
- Game tests only: `./gradlew runGameTest`. Headless server; the exit code is the number of failed required tests (non-zero fails the build). JUnit report: `build/gametest-report.xml`.
- Dev client: `./gradlew runDevClient` ("Dev Client"). Opens the singleplayer world `run/saves/a1016_dev`, creating it on first launch: creative, cheats on, user `Dev`, seed `-4180345853331630785` (spawn in a Dappled Forest; cold ocean and snowy slopes ~90 blocks, frozen peaks ~100). Delete the folder to start over. Plain `./gradlew runClient` still works.
- Server: `./gradlew runServer` (dir `run/`; it needs `run/eula.txt` with `eula=true`, which only Mariano accepts). The console takes commands on stdin, e.g. `a1016 state`, then `stop`, once the server says `Done`. Lines piped in at once (`printf '...\nstop\n' | ./gradlew runServer`) are read while it is still starting, and every one of them, vanilla `stop` included, answers "An unexpected error occurred": vanilla makes each console line's source as it reads it, and before any level exists that source has none, so `Commands.executeCommandInContext` fails on it before any command runs. Not the mod's (`DebugGameTests.consoleLinesReadBeforeTheWorldLoadsFailInVanillaToo`); wait for `Done`, or feed lines later.

## Code guardrails (the reviewer checks every one)
1. Every block, item or light change that "he" makes goes through `TraceService`. Every mob manipulation goes through `MobTamper`. The only exemptions are worldgen features and structures, which place blocks during chunk generation where nobody can see them, and D-047 (see TraceService).
2. Never damage, target or touch the player. Never spawn a mob. The figure entity (owned by entity) is the only entity the mod spawns. Fake sightings use mobs that already exist.
3. Nothing changes in the player's view: use `TraceService.isOutOfView`. The only in-view changes: the figure's dig-under (D-030), the fall after `removeLettingFall` (D-038), Ending D's last minute giving back (`restoreVisibly`/`regrowVisibly`, D-048), and the glimpse vanishing as it is looked at (D-073, that variant only; it never edits a block).
4. All timings come from `Pacing` or your config section. No hardcoded faster timings. `devFastMode` defaults to false.
5. In-game text never names real people, companies or forums. Use only "the developer", "the studio", "the team".
6. Fragment text matches DESIGN.md word for word.
7. Every accident is deniable and leaves exactly one clue.

### HerobrineState (`HerobrineState.get(server)`, file `data/a1016_02/state.dat`)
One per world: one shared story (D-058) with personal records per player (D-061). Change it only through its methods, which mark it dirty. The first `get` rolls the profile with a new random salt.
- `stage()`: `Stage` {ALONE 0, TRACES 1, PROXIMITY 2, TELLING 3, REMOVAL 4}. `setStage(server, stage)` fires `STAGE_CHANGED`.
- `attention()`: double, 0 to 100, one value for the world. `tension(UUID)`: that player's director tension, 0 to 100 (D-059); 0 for someone unknown. Both clamped; change them only through `Attention`.
- `profile()`: `WorldProfile`; `reroll(seed, salt)`. The salt is hidden (package-private). `worldgenSalt()`: derived from it once, then fixed for the world (a reroll keeps it); read it at server start for worldgen hashing.
- Known players: everyone who has ever been a participant, in first-join order. `List<Subject> players()`, `Optional<Subject> player(UUID)` (a known player's record `Subject(uuid, name)`, the name as of their latest join). Core records a player once they take part (a spectator who never plays is never known). Each known player has their own first blocks, play ticks (`GameClock.playTicks(server, uuid)`) and tension; someone who first takes part later starts with empty records and zero play ticks, never anyone else's. Tests and debug only: `addKnownPlayer(uuid, name[, FirstBlocks])` makes a known player of a private state (at the end of the join order, zero play ticks; each first block only where that slot is empty; someone already known only takes the new name). Game code never calls it.
- Owners (D-061): `Optional<UUID> owner(key)`, `owners()`, `clearOwner(key)` (debug and tests only). Choose through `PlayerWatch.ownerFor` (migrations: `adoptOwner`). `hasPlacedBlock(uuid)` (the player has a first block) is the one rule for who may become `story:first_blocks`: lore, world and the ending all pass `state::hasPlacedBlock`.
- `stopFired / listRead / tellingStarted` with setters. `tellingCount()` + `incrementTellingCount()` (lore counts every telling, D-039; the increment keeps the flag `lore:telling_count=<n>` in sync for older readers). `fragmentsRead()` (read by anyone: story fragments and the clues past F30) + `markFragmentRead(id)`. `fragmentsPlaced()` + `setFragmentPlaced(id, GlobalPos|null)`.
- Marked deaths, one shared list that records whose each death was (D-063): `markedDeaths()` (everyone's, oldest first), `markedDeaths(UUID)` (that player's), `addMarkedDeath(UUID player, MarkedDeath(cause, GlobalPos, day))` (stores it as that player's; `MarkedDeath` has a fourth field `player`, null only before it is added).
- `firstBlocks(UUID)`: that player's `FirstBlocks(block, craftingTable, chest)`, each a `PlacedBlock(GlobalPos, BlockState)` or null; `FirstBlocks.NONE` for someone unknown. Recorded by `PlayerWatch` from each participant's own placements.
- Old saves (D-062.8): a v1.0 `state.dat` (top-level `subject`, `firstBlocks`, `tension`, and the subject's ticks in `clock.playTicks`) loads as one known player with those first blocks, that tension and those play ticks; its marked deaths become that player's, and, if they placed a block, they adopt `V1_OWNER_KEYS` (`story:first_blocks`, `ending:home`): the story so far was theirs, so a friend who is online alone first never takes it over. The new format stores `players` (each with `uuid`, `name`, `firstBlocks`, `playTicks`, `tension`) and `owners`, and never writes the old fields.
- `effects()`: `Effects(musicOff, duskFogLevel, Optional<FogSpell> fogSpell)` (the two-argument constructor has no spell; `withFogSpell(spell)`). Change through `ClientEffects`; sent again on every join. A save from before fog weather has no `fogSpell` and loads with none.
- `flags()`, `hasFlag(f)`, `setFlag(f, bool)`: free namespaced flags (`"lore:f04_done"`). Use them instead of asking for a new field. Shared ones: `ending:last_sighting` (set by ending: Ending A's last sighting may happen), `entity:last_sighting_seen` (set by entity: that figure was seen and is gone), `lore:still_burning` (set by world when its one still-burning camp is built, D-004; lore then puts F21 in that camp's emptied house only), `ending:path=<A|B|C|D>`, `ending:ended` (the story is over) and `ending:d_complete` (set by ending; the house copy stops for good after either of the last two), `ending:line_finished=<uuid>` (set by ending, one per player: that player's line was finished, by a hardcore marked death (D-063: they stay a spectator, and the story ends only once nobody online is left in it) or by Ending B's final death inside the copy; F10's "* removed" lines name exactly these, in order), `ending:d_step=<n>` and `ending:d_step_day=<day>` (set by ending on every advance of Ending D's chain: the step, 1 to 9, and the in-game day, on the world clock, it was reached; step 1's day is when F23 was first read; lore's late clues F38 to F44 read them, D-066), `ending:last_minute` (set by Ending D only while a real last minute gives back in view, D-048; never by the debug preview, cleared on reset and server stop; no sighting starts while it is set), `director:silence_forever` (set by the endings; while it or `ending:path=C` is set, no atmosphere fog surge or drift and the house copy waits), `director:obeyed_after_stop` (set by the director while OBEYED_AFTER_STOP has fired and nobody in the group told since, D-064; anyone's telling clears it at once; Ending A's obey rule), `entity:stared` (set by entity the first time anyone stares him down).

### Attention
`Attention.trigger(server, AttentionTrigger.X)` applies the configured weight of a Triggers row (`DISC_13_UNDERGROUND`, `NAMED_HIM`, `WROTE_NEAR_TRACES`, `ENTERED_TUNNEL`, `DUG_INTO_PYRAMID`, `REPLANTED_GROVE`, `CARRYING_LIST`, `RULES_BOOK_NEAR_BASE`, `LOW_RENDER_DISTANCE`, `SLEPT`, `STARED_AT_HIM`, `DESTROYED_OWN_WRITING`, `OBEYED_AFTER_STOP`, `AVOIDED_TRACES`, `LEFT_GROVES_ALONE`, `STOPPED_DISC_13`, `DAYLIGHT_OPEN_AREAS`, `LIST_IN_LAVA`). Also `raise/lower(server, amount, reason)` for attention (one value for the world: anyone's actions count, D-058) and `raiseTension/lowerTension(server, UUID player, amount, reason)` for that player's tension (nothing for someone who was never a participant). There is no world-level tension.

### WorldProfile (record)
`habits` (2 of `Habit` {CARVER, STRIPPER, WATCHER, MOURNER, COLLECTOR, VISITOR}), `density` {SPARSE, NORMAL, HEAVY}, `tempo` {EARLY, SLOW_BURN, VERY_LATE}, `fragments: Set<String>`, `signature` {STILL_BURNING, HOUSE_ELSEWHERE, CROSS_ROW}. `WorldProfile.roll(seed, salt)` is deterministic: `FIXED_FRAGMENTS` (11: D-003's ten plus F08, D-066) plus 11 to 13 of the other story fragments rolled, with `DEPENDENCIES` (D-003); every profile holds the fixed ones, so an old save gains F08. `storyFragmentIds()` is F01 to F30 (what a world rolls), `allFragmentIds()` those plus `CLUE_FRAGMENTS` (F35, F36, F38 to F44: the chamber plates, the team's note and the late clues), which are never rolled or listed in `fragments` but always enabled: `isEnabled(id)` is the question to ask (rolled, fixed or a clue). `tempo.paceFactor()` is 0.75 / 1.0 / 1.25 (`Pacing.tempoShift` 0.25, D-070). `hasStillBurning()` (D-004) and `hasHouseCopy()` (D-005) fold in F21 and F27.

### EventCard
```java
String id();                  // unique snake_case, e.g. "fog_drift", "sighting_cow"
Tier tier();                  // AMBIENT, MINOR, MAJOR, SIGNATURE
Stage earliestStage();
Set<Habit> habits();          // weighting; empty = neutral
Set<CardTag> tags();          // SOUND SIGHTING SCAR FOG MOB ACCIDENT ITEM LIGHT TEXT DIG PERSONAL BLIND
boolean hasFake();            // can fire as a false positive
boolean contextFits(ServerPlayer player, ServerLevel world);
FireResult fire(FireContext ctx);  // record(player, level, fake, forced, random); FIRED | NO_SPOT | SKIPPED
```
Register cards in `init()` with `Director.register(card)` (stored in `CardRegistry`: `get(id)`, `all()`, `ids()`, `byTier(t)`), which works before the director is installed. When `fire` gets `NO_SPOT` (no out-of-view place exists right now), the director keeps the card for later. Sample: debug's `debug_ping` (its context never fits; for `/a1016 fire`), registered only in a development environment (`FabricLoader.isDevelopmentEnvironment()`: the dev client and the game tests), never in a release jar. `CardTag.PERSONAL` (D-074) marks a card for one player alone (dig's tunnel ladder): the director never draws it while the player has sharers (`PlayerWatch.sharingWith` lists anyone besides them), and a held PERSONAL card goes back into its deck as soon as a sharer comes close, so it never blocks its tier while friends stand together; the card still checks being alone itself when it fires. `CardTag.BLIND` (D-077) marks a card whose moment is a blind moment (`PlayerWatch.blindTicks` > 0: dig's blind step, torch and door): a held BLIND card keeps the normal hold (`holdGiveUpMinutes`, 60) instead of the 5-minute unfit give-back, since a menu comes often, and the director rechecks it first when core calls `Director.recheck`; the card still checks the blind moment itself when it fires.

### Director (`Services.director()`)
`tick(server)` runs every server tick; the impl picks its own cadence (`Pacing.directorTickTicks()`).
- A pacing per player (D-059). The director's memory (`data/a1016_02/director.dat`) is one world part (the stage clock on the world clock, the once-per-world signatures, the world's tag times, and the triggers that count once per occasion: SLEPT once a night however many sleep, disc 13 once per jukebox, daylight, AVOIDED_TRACES, and OBEYED_AFTER_STOP for the group, D-064) plus a pacing per known player by UUID (session and join grace, empty sessions, gaps and hard limits, their own first in-game day, major slot, tension's quiet, pity, decks with their holds and no-repeat cycles, history, low render distance once per session), each measured on that player's own clock. Every targetable participant decides on their own staggered cadence; sessions follow `PARTICIPATION`, per player. A v1.0 `director.dat` loads as the world part plus the first known player's pacing. Pacings are never pruned: the file grows by one small entry per player who ever took part (fine for co-op). The first-day rule counts from each player's own first participation, so on a world that got the mod mid-game majors wait one in-game day where v1.0 allowed them (intended).
- Felt moments (D-060.3). A card fires for the player whose pacing picked it, and only if every other targetable participant within `sharedMomentRadius` of them (the sharers) could have had it on their own (every gate of theirs open, the card new to them). It then counts as felt by each sharer: their gaps and hard limits, major slot, Alone cap, sightings per day, no-repeat cycle, tension and the quiet it may start, but not their own draws or fire counts. Together, the group rolls `groupRateFactor` (1.5) solo ambient and minor rates between them, each a share (D-074; v1.1 split exactly one), the factor applied before the refractory wait after a fire, so the wait is the group rate's; a draw never picks a card a sharer already had, and such cards count as spent for the run-out rule, so a deck whose only undrawn cards a friend had refills at once when that gives back a card new to everyone there (otherwise the cycle is kept), and a used-up deck refills by the solo rule, so the pair's decks turn over together and never deadlock; a card held from before a friend who already had it came close goes back into the deck at once. Sessions share one mood: one started next to someone takes that session's mood (empty or not), and when sessions that started apart meet, every later one takes the earliest one's mood (`Recorder.sessionMood`, the sim's `MOOD` event), so a friend's empty session rolled far away never silences the other for its whole length. A friend's quiet still holds the shared moment (anything that fired would reach them). Alone, everything is the solo pace exactly (solo runs are identical whatever `groupRateFactor` is).
- v1.2 (D-070, D-071, D-074, D-075). DirectorConfig (section version 2) has v1.2's rates (`aloneAmbientPerHour` 4.5, `proximityAmbientPerHour` 2.5, `tracesMinorsPerHour` 1, the Alone and Traces tag weights) and new fields: `firstHourMaxFires` (5: a gate, a player's own first hour of play never holds more than five moments, their own and felt; `DirectorBrain.firstHourFull`), `heldUnfitGiveBackMinutes` (5: a held ambient or minor card whose context has not fit at a whole 5 minutes of looks goes back into its deck and the next draw passes it over if it can; majors and signatures keep `holdGiveUpMinutes`, 60), `unfitParkMinutes` (30, version 2), `emptySessionMinStage` (PROXIMITY), `groupRateFactor` (1.5), `fogWeatherOddsFactor` (3.5), `fogWeatherSightingWeight` (3) and `fogWeatherMajorPullMinutes` (60). Cards whose moment never comes (FIX-DIR, R1#1): a hold's looks are counted one per director tick in `PacingMemory.unfitLooks`, and a look a gate held back (the gap after a fire, a quiet, an empty session, a friend's gates) does not count. An ambient or minor hold that failed every look for `heldUnfitGiveBackMinutes`, or a major or signature held `holdGiveUpMinutes` that failed that many looks, goes back and is parked for `unfitParkMinutes` of the player's play (`PacingMemory.parkedUntil(cardId)`, -1 if none; saved in `director.dat`; `DirectorBrain.parked`): never drawn, and ruled out for the run-out rule, so its deck refills with the cards that can fire. A parked ambient or minor hands the roll that drew it to the next card in the same tick (at most 2 a tick, `MAX_CARRIED`). After its park it is drawn as any other card; until it fires or is felt (either ends the park), a hold of it goes back, parked again, after one look that does not fit (struck). Every director tick each parked or struck card's moment is looked at in passing, whatever the gates (`DirectorBrain.releaseFitting`: `contextFits` only, at most one look per registered card): one whose moment fits is released there, park and strike (its `parkedUntil` entry goes), and is drawn again with whole holds, so a card whose moment is a short stretch of every day (the ridge's dusk) is not starved; one whose moment never comes is never released (FIX-FINAL). Give-backs that park say so ("its moment did not come (parked)", "held too long (parked)"); `DirectorSim.Params.neverFits` plays cards whose moment never comes; `unfitParkMinutes` 0 turns parking off. `PERSONAL` is a stage rule while anyone shares the moment: such a card is never drawn, never holds a deck's refill back (no deadlock), and one held goes back at once, before any gate. Fog weather: `DirectorBrain.Env.fogSpell()` (default none) is the spell on for the player: live, the stored spell on their level's clock while it counts (`FogSpell.counts`: its amount at least `fogGateShare`, 0.5, of its level), none in fixed-time dimensions (`DirectorImpl.fogSpellOn`); in dry runs, one sky rolled with `FogWeatherRules` on dice of its own at the live roll times (`nightRollTime`, `dayRollTime`) and joined with `handOver`, read through the same gate share (`spellNow`: a spell's thin ticks are booked as a clear sky); live sims start from the stored spell moved onto the run's clock (`withClocks`) and the installed numbers. A spell that counts and is not quiet multiplies the ambient and minor rate by `fogWeatherOddsFactor` (the refractory wait included), the SIGHTING stage weight by `fogWeatherSightingWeight`, and makes a major slot due within `fogWeatherMajorPullMinutes` due now; quiet spells and a spell's first and last ticks give nothing; `/a1016 director` prints the fog weather line ("below half: no boost" for a spell on but not counting). Rules versions (D-075): `WorldMemory.rulesVersion` and `PacingMemory.rulesVersion` (`WorldMemory.RULES_VERSION`, 1; missing is 0). A v0 world rolls its stage points again in the new windows on its first time step (`Recorder.rulesUpgraded(clock, fromVersion, tracesAt, proximityAt)`): a stage reached stays reached, and a world still in Alone past its new Traces point starts Traces now, Proximity its rolled stretch later. A v0 pacing rolls its next major slot again at its next session, never later than it was. `DirectorSim` books each run's time and fires per `Sky` (CLEAR, QUIET, FOG) and lists its spells (`Result.fogSpells`); its `check` replays the first hour's cap and empty sessions from Proximity.
- `FireResult fire(server, ServerPlayer player, cardId, fake)` is for debug: it fires for that player, skips gates and pacing but never the out-of-view rule; `SKIPPED` if the card is unknown or the player is not targetable (`PlayerWatch.isTargetable`: not a participant, or dead). A forced fire goes into the target's history, deck and tag times, never their gaps, tension or quiet, and the same for each sharer. Every fire is for a player: `/a1016 fire` from the console takes the first participant (D-062.9).
- `List<String> timewarp(server, days)`: every clock moves (`GameClock.warp`), then what time alone does (stages, each player's tension decay and quiet running out); the summary lines are a dry run of the first participant's pacing (else the first known player's, else a fresh one). `/a1016 timewarp <days>` and `/a1016 director timewarp <days> [player]` print them.
- `ticksSinceTag(server, CardTag)` is the world's answer: world-clock ticks since a card with the tag fired for anyone (`Long.MAX_VALUE` if never), for what the whole story waits on (the endings' accident gap). `ticksSinceTag(server, UUID, CardTag)` is that player's: their own clock since one fired for them or reached them as felt; a gap that is pacing asks this one (atmosphere's mining-in-the-dark sound gap). `inQuiet(server)`: any participant is in a forced quiet of their own (the conservative answer for one flag); `inQuiet(server, UUID)`: that player is. The per-player forms are interface defaults that give the world's answer (the stub), real on the director.
- `recheck(server, ServerPlayer player)` (D-077; an interface default that does nothing, so the stub does nothing; the director implements it): a blind moment's recheck. Core calls it for a player whose client has a counting screen open, `PlayerWatch.BLIND_FIRST_RECHECK_TICKS` (30) ticks after the moment starts and every `BLIND_RECHECK_EVERY_TICKS` (20) while it lasts, at most `BLIND_MAX_RECHECKS` (10) times (blind ticks 30, 50 ... 210), on the server thread, at the end of the server tick before `tick`. For that player only: fire their held or parked card if its moment fits now (`contextFits`) and every gate the normal decision uses passes (silence, grace, quiet, empty session, gaps, caps, sharers, PERSONAL), BLIND cards first; never a new roll or draw. A watch's rechecks go to `PlayerWatch.Source.director()` (the live director; tests pass their own).
- `List<String> debugLines(server)` for `/a1016 state`: the world part, then each participant's own pacing. The stub's `fire` calls the card directly (and fires `CARD_FIRED`); its `timewarp` calls `GameClock.warp`. Dry runs (`DirectorSim`; `runGroup` for several players, where the world clock and the stage stand still while nobody is seated) reach Telling only when someone names him at a set hour (`simTellingAtHour`, `/a1016 director sim <h> telling <atHour>`); the director never enters it alone (D-041).

### TraceService (`Services.traces()`, real)
- `isOutOfView(ServerLevel, BlockPos | AABB | Collection<BlockPos>)`: false if any player is within 3 blocks of it, or has line of sight inside a 160° cone within the server view distance. Only opaque full blocks (`isSolidRender`) block sight; glass, leaves, ice and doors do not. The collection form checks every block with a see-through neighbour. Unloaded points count as unseen. D-027: the 3-block rule skips a block strictly below a player's feet, in the columns their hitbox overlaps, while they look 30°+ up and it is outside the cone. Geometry for tests: `static isOutOfView(level, box, viewers, near, cone)`, `positionsOutOfView(level, positions, viewers, near, cone)`, `Viewer.of(player, chunks)`.

### PlayerWatch (`Services.watch()`, real)
Everyone takes part in the one story (D-058): a participant is an online player who is not a spectator. A dead player on the death screen still takes part (a death does not flap sessions or clocks); a hardcore death makes them a spectator, and then they stop.
- `List<ServerPlayer> participants(server)`: every participant, in first-join order (the order they first took part in this world; anyone not recorded yet comes after, by UUID). A new list each call.
- `isParticipant(player)`: this very object is online (a stale object from before a respawn is not) and not a spectator. `isTargetable(player)`: a participant who is alive and not removed, "may something happen to this player right now". Spectators are never targeted (D-062.7) but still count as viewers for every out-of-view rule.
- `Optional<ServerPlayer> participant(server, UUID)`: a fresh lookup, empty when offline or not a participant. D-062.1: keep UUIDs, never `ServerPlayer` objects across ticks or events; look the player up again and skip quietly if it comes back empty.
- `List<ServerPlayer> sharingWith(target)` (D-060): the target first (even if not a participant or not targetable), then every other targetable participant in the target's level within `Pacing.sharedMomentRadius` blocks of them, in join order.
- Stored owners (D-061): `Optional<UUID> owner(server, key)` is the stored choice; `Optional<UUID> ownerFor(server, key)` returns it, or if none is stored chooses now among the online participants (most play ticks of their own, ties to the earliest first join), stores it and returns it; empty, storing nothing, when nobody takes part. `ownerFor(server, key, Predicate<UUID> eligible)` chooses only among the participants `eligible` accepts (empty, storing nothing, while none is); a stored choice is returned as it is, whatever the predicate says now. `adoptOwner(server, key, uuid)` is for migrations: it stores a known player only where nothing is stored yet, online or not, and never replaces a choice (returns the stored owner; empty for someone who never took part). Choices persist and never flip. Keys are `"<ws>:<what>"`. Shared keys: `story:first_blocks` (`LoreApi.FIRST_BLOCKS_OWNER`, `EndingApi.FIRST_BLOCKS_OWNER`, `world.Bases.STORY_OWNER`: whose first crafting table, chest and block the story uses, and whose base the story's "near your base" fragments measure from, remembered while they are away: lore's F13 cairn and F10, ending D's cairn block and his cross, `MissingFirstBlockCard`, world's still-burning F21 camp; whoever needs it first chooses it, always with `state::hasPlacedBlock`), `world:house_copy` (`HouseCopyApi.OWNER_KEY`, `EndingApi.HOUSE_COPY_OWNER`: whose house the copy copies: world chooses it when the copy starts, among the participants whose first shelter in the overworld can be captured, never in a card's context check; a copy from before multiplayer adopts its first known player at once; F27 follows it) and `ending:home` (`EndingApi.HOME_OWNER`: whose base is "your house" for the group: Ending C's house taken apart, and Ending B's house when there is no house copy; the ending chooses it among the participants who have a base, and while its owner is away anyone's bigger house far from it becomes the home). A v1.0 save's subject adopts `story:first_blocks` and `ending:home` (`HerobrineState.V1_OWNER_KEYS`). Any other key is `<ws>:<what>` in its own workstream.
- Per player: `stillTicks(player)` (position only), `ticksSinceCombat(player)`, `ticksSinceJoin(player)`, `isSleeping(player)`, `Optional<GlobalPos> base(player)` (respawn point, else that player's own first block).
- Recent actions (D-076, D-079), per participant and for their session only: `List<PlayerAction> recentActions(player)` is what they did lately, newest first, at most `RECENT_ACTIONS` (64) entries, a new list each call. `PlayerAction` (sealed, immutable; `dimension()`, `pos()`, `tick()` on the server's tick count, `getTickCount()`) is one of: `Mining(dimension, List<Break> breaks)`, a run of blocks broken one after another (`Break(pos, state, tick)`, the state just before the break), oldest first, each less than `Mining.GAP_TICKS` (60 ticks, 3 s, real ticks) after the one before, in one level, with no door or container between them, at most `Mining.MAX_BREAKS` (6) to an entry (a longer run goes on in a new entry, so strip mining is a string of sixes and 64 entries hold up to 384 breaks); `isBurst()` (2 to 6 breaks, `MIN_BURST`), `first()`, `last()`, `firstTick()`, `gaps()` (ticks from each break to the next); `pos()` and `tick()` are the last break's. `DoorUse(dimension, pos, state, tick)`: a door (at its lower half), trapdoor or fence gate opened or closed by hand, `state` right after the use (its own sounds come from its block), `opened()`. `ContainerOpen(dimension, pos, state, tick)`: a block whose block entity is a `Container`, or an ender chest, whose menu opened (the clicked half of a double chest). Every break counts (a player-placed block, a plant, a torch: cards choose by state). `recentBursts(player)` is the mining entries that are bursts, newest first. Breaks come from Fabric's `PlayerBlockBreakEvents.AFTER` (`onMined`), doors and containers from core's `ServerPlayerGameModeMixin` on `useItemOn` (`onUsedBlock`: the block's state and the player's menu before and after; an iron door clicked by hand changes nothing and is not recorded). Only participants are recorded; the actions are forgotten when the player stops taking part (PARTICIPATION false: they left or turned spectator) and on server stop, and kept through a death. Tests and debug: `addBreak(player, dimension, pos, state, tick)` (grouped as the hook groups) and `addAction(player, action)` (as it is), both ignored for a non-participant.
- Blind moments (D-077), per participant and per session: `long blindTicks(player)` is the ticks since their client said a counting screen opened (core's `BlindState` payload, below), at least 1 from the moment it starts, 0 when not blind. It ends when the client says the screen closed, and is reset when they disconnect, stop taking part, die or change dimension (a screen still open then counts again only once the client says so again; core's client sends again for a new player object). The server takes the signal from living participants only and the signal only ever makes things happen to the player who sends it; a second "open" keeps the moment going. Counted at the end of each server tick (after participation, before the director); each moment brings the director's rechecks (`Director.recheck`, at blind ticks 30, 50 ... 210). Tests and debug: `onBlindState(player, blind)` (as the client would) and `markBlind(player, ticks)` (blind as if for that long, its earlier rechecks counted done), both ignored for someone who is not a living participant.
- `lastVisitDay(level, ChunkPos)`: the day a participant was last there (-1 if never; sampled every 5 s, 3x3 chunks; spectators do not count). Footprint (all players, capped per dimension): `wasPlacedByPlayer(level, pos)`, `wasDugByPlayer(level, pos)`, `placedNear(level, center, radius, Block | TagKey<Block> | Predicate<BlockState>)` and `dugNear(level, center, radius)` return `List<BlockPos>`. Placement comes from core's `BlockItemMixin`; a participant's placement also records their own first block, crafting table and chest. A cell is placed or dug, never both: breaking a natural block marks it dug, breaking a placed block drops its placed mark, and a block placed in a dug cell takes the dug mark away only while it stands (breaking it gives the mark back, so a torch picked up again or cobble placed and mined never cuts a dug tunnel; `watch.dat`'s `dugUnder`, missing in older saves).
- Sessions: listen to `HerobrineEvents.PARTICIPATION` instead of Fabric's JOIN and DISCONNECT.
- `PlayerWatch.Source` (tests' own online list, state and participation events) also gives `director()`, where that watch's blind rechecks go (default `Services.director()`).

### GameClock

### FogLimits (static, both sides)
`FogLimits.of(player)` (server) or `of(clientChunks, serverChunks, duskFogLevel, dayTime)` gives `Result(chunks, renderLimit, fogEnd)`: the un-pulled render limit (`min(client, server) * 16`) and the fog end after the dusk fog, by atmosphere's client curve (`duskWeight`, `fogEnd`). Atmosphere owns the shape: `installShape(() -> AtmosphereConfig.get().fogShape())`. With fog weather (D-071) the dusk amount (`level * duskWeight`) and the fog spell's amount combine as `combine(a, b) = 1 - (1 - a)(1 - b)` (either at 0 gives the other exactly, so without a spell every result is bit for bit what it was) before the same pull toward `duskMinFogBlocks`. A spell's amount is always its own ease (`FogSpell.amount(clock)`), so client and server get the same number from the same spell whatever their configs. Forms: `of(player)` reads the stored spell (`HerobrineState.Effects.fogSpell`) on the player's level clock (`getDefaultClockTime()`), neither dusk fog nor spell in fixed-time dimensions, and weights the spell (not the dusk fog) by `skyFactor` of the sky light at the player's eyes: the spell is weather, outside, as vanilla gates its rain fog on the sky; `of(clientChunks, serverChunks, dusk, clockTime, Optional<FogSpell>)` with the installed shape (no sky weight), or `of(..., spell, Shape, FogWeatherRules.Settings)` (the settings are not read any more, kept so older calls compile); the pure form `of(clientChunks, serverChunks, dusk, dayTime, Shape, double spellAmount)`; `spellAmount(spell, clockTime)` (and `spellAmount(spell, clockTime, settings)`, the same). `skyFactor(int skyLight)` (pure): 1 at sky light `SKY_FULL` (10) or more, 0 at `SKY_NONE` (4) or less, linear between (the raw sky light, not darkened by the time of day); atmosphere's client applies the same factor at the camera, smoothed as vanilla smooths its rain fog, to the spell's fog distance and its tint. The old `of(c, s, dusk, dayTime[, shape])` forms have no spell. The client does the same math in `ClientAtmosphere.applyFog`, so the figure's band follows a fog night even without a fresh client report.

### Fog weather (`FogSpell`, `FogWeatherRules`, D-071)
- `FogSpell(fromClock, untilClock, level, quiet, rampTicks, fadeTicks, exponent)` (record, `CODEC`, `STREAM_CODEC`): one spell of fog weather for the whole world on the overworld clock (absolute `getDefaultClockTime()` ticks, so client and server agree and sleeping through a fog night lands in its morning). The ease is the spell's own: set from the settings when the spell is made (`FogSpell(from, until, level, quiet, Settings)`; the old four-number `FogSpell(from, until, level, quiet)` takes the installed `FogWeatherRules.settings()`), carried in the save (`ramp`, `fade`, `exponent`, optional: a spell saved without them, v1.2.0, takes the installed settings when it loads) and always in the stream codec, so a client draws the server's ease whatever its own config. `amount(clock)`: `level` times the smaller of the ease in over `rampTicks` from `fromClock` and the ease out over `fadeTicks` before `untilClock` (`FogLimits.ease` with `exponent`, the dusk fog's 3), 0 outside, continuous everywhere (a spell shorter than its ramp and fade never reaches full); `amount(clock, settings)` is the same (the settings are not read, kept so older calls compile); `amount(clock, ramp, fade, exponent)` is the pure ease with other numbers. `counts(clock)` is the one "is there fog now" rule for everyone who gates on it (the director's boost, daytime sightings): the spell gives fog and its amount is at least the installed `Settings.fogGateShare` (0.5) of its level, so its first and last ticks and a carry-over's tail do not count; `counts(clock, share)` with another share. `activeAt(clock)`, `endedBy(clock)`, `withClocks(from, until)` (the same level, quiet and ease). `untilClock` is never before `fromClock`, `level` is in 0 to 1, the ramp and fade 0 or more, the exponent 1 to 8. `quiet`: no director boost.
- `FogWeatherRules` (pure, used by atmosphere's live weather and the director's sims): `night(random, day, stage, history[, settings])` (tonight's roll for the night starting on clock day `day`: a spell 11500 to 23500, or on to 5500 of the next day for a morning carry-over, at the stage's night level, quiet at `quietShare`; empty for a clear night), `foggyNight(random, stage, history, settings)` (the rule alone: the first night never, the second at `secondNightChance`, the third always if neither before was, always after `clearNightsBeforeFog` clear nights, never right after a fog night in Alone or Traces, else the stage's chance), `day(random, day, stage, history, current[, settings])` (a fog day from 23000 of the day before to 11500: never in Alone, never right after a fog day, never when `covers(current, day)`, i.e. a morning carry-over runs into it), `handOver(current, next, now[, settings])` (the spell to store when `next` rolls while `current` still gives fog: one spell going on from exactly the fog there is now, `current`'s own amount, easing up to `next`'s level, ending like `next`, with the settings' ease; no pop on either side; a spell handed over never thins after the roll, so roll before the current spell's fade starts to keep it from thinning at all), `nightFrom/nightUntil/dayFrom/dayUntil(day)` and the time constants. Every spell the rules make carries the settings' ease. The roll times are core's too: `NIGHT_ROLL` (10000: tonight, with its morning carry-over, rolled before a fog day still at full starts its fade, so the hand-over never thins) and `nightRollTime(settings)` (`NIGHT_ROLL`, earlier only when a fade longer than the default needs it); `DAY_ROLL` (21500 of the day before: `NIGHT_UNTIL` minus the default fade minus `DAY_ROLL_LEAD` 500, so a fog night without a carry-over is still at full when the next day's fog day rolls and never thins before dawn) and `dayRollTime(settings)` (`DAY_ROLL`, earlier only for a longer fade, never before `NIGHT_FROM` nor after `DAY_FROM`); atmosphere's live weather (`FogWeather.dayIndex(clock, settings)`) and the director's dry runs both roll then. Callers check what only they know: nothing once the world is quiet for good, nothing shown in fixed-time dimensions. `History(nights, clearNights, lastNightFoggy, lastDayFoggy)` (`START`, `CODEC`, `afterNight(foggy)`, `afterDay(foggy)`; a day a carry-over covered is `afterDay(false)`): the first-nights rules count the nights rolled, so a world that got the mod late starts with a clear night too. `Settings` (record, `DEFAULT` = D-071's numbers: night chances {0.25, 0.33, 0.4, 0.45, 0.5}, second night 0.5, 4 clear nights, carry-over 0.35, day chances {0, 0.06, 0.1, 0.12, 0.12}, night levels {0.45, 0.55, 0.65, 0.72, 0.8}, day levels {0.4, 0.45, 0.55, 0.6, 0.65}, quiet 0.25, ramp 2500, fade 1500, exponent 3, `fogGateShare` 0.5 (`DEFAULT_GATE_SHARE`; the eleven-number constructor has it); lists by `Stage.level()`, normalized to 5 entries, everything clamped; `perStage(double... | float[])`), installed by atmosphere from its config section the way it installs the shape (`FogWeatherRules.install(supplier)`, any thread), read with `settings()`; until then the defaults hold.

### Events (`core.HerobrineEvents`, Fabric `Event`)
`STAGE_CHANGED(server, old, new)`, `TELLING(player, text, pos, namesHim)` (fired by lore), `FRAGMENT_READ(player, id)`, `MARKED_DEATH(player, cause, pos)`, `CARD_FIRED(player, cardId, fake)`. `PARTICIPATION(server, UUID player, participating)` (fired by core): exactly once per change, `true` when a player joins as a non-spectator or leaves spectator mode, `false` when they disconnect while a participant or become a spectator; never for a spectator who joins and leaves, never on server stop; a death or an ordinary respawn changes nothing (a hardcore respawn as a spectator is a stop). ### Config (`config/a1016_02.json`)
`ModConfig.pacing()` is `Pacing`: every number from DESIGN.md "The director", 4b, Triggers and related rules, in natural units, plus `...Ticks()` accessors (and `TickRange tracesStart(tempo)` etc.) that divide by `devFastDivisor` when `devFastMode` is true (default false). Use `ModConfig.realTicks(seconds)` for your own real-time values; cost cadences and chunk-load timeouts are plain ticks, named and commented. Multiplayer: `sharedMomentRadius` (blocks, default 48): participants this close to the target, in the same dimension, share its fog surges, silences and fired cards (D-060). Workstream tunables: `ModConfig.section("<ws>", Type.class, Type::new)` (public fields, no-arg constructor), stored under `sections.<ws>`. `ModConfig.saveSection(name, value)` writes one section back for a live edit (only `sections.<name>` changes in the file; `section` returns `value` from then on).

Reading is lenient, so the game always starts and a typo costs one value: the root, `pacing` and every section are read value by value into their defaults (Gson's rules for each value; unknown keys skipped). A value that cannot be read (a string in a number field, a fraction in an int, a wrong shape, null) keeps that field's default and logs one warning naming its key (`pacing.tracesStartMaxHours`, `sections.director.minAnyGapMinutes`); every other value in the file is kept, and the next write puts the default in place of the bad one. A section that is not an object reads as its defaults. A file that is not JSON at all is copied to `config/a1016_02.json.broken` before the defaults are written.

Versions (D-075): the root's `configVersion` (`ModConfig.CONFIG_VERSION`, 1 since v1.2) covers the root and `Pacing`; each section keeps its own `public int version = 0` (0 in the field, so a file without it reads as v1.1 or older). On load every part is upgraded one version at a time and the new version is written: a step replaces a value that still equals the old default with the new one and keeps anything the player changed. `Pacing.upgrade` holds the root's steps (0 to 1: D-070's numbers, with the stage windows kept in order: a window half set by hand keeps the player's whole window, and a Traces window slowed by hand past v1.2's Proximity start keeps the player's old Proximity window, so Proximity never starts inside Traces). A section implements `ModConfig.Versioned` (`boolean upgrade()`: true if anything changed, the version included); `section` runs it once, on the first read, from the file or from fresh defaults (where it leaves every value as it is, and logs nothing: the "upgraded to new defaults" line is only for a section read from the file), before anyone sees the section, and writes the result; `ModConfig.readSection(sectionsJson, name, Type.class, Type::new)` is that read without the cache or the file, for a section's upgrade tests. Steps use `ModConfig.Upgrades.keepOrNew(current, oldDefault, newDefault)` for double, float, int, long, boolean, String, float[] and double[] (element by element; a reshaped array is kept whole), `weights(current, old, new)` for a weight map and `tagWeights(current, old, new)` for the director's stage-to-tag map (an entry still at its old default takes the new one, a missing new default removes it, the player's changes, additions and removals stay); numbers compare within `Upgrades.EPSILON` (1e-6, relative) of the old default, so a value that went through a float still counts as unchanged. Every later default change adds a step and raises the version.

Multiplayer fields in the sections: `world.newScarWorldGapDays` (1: at most one real new scar per in-game day in the whole world), `world.houseCopyBaseClearance` and `world.stillBurningBaseClearance` (64 blocks from every known base), `dig.networkShareDistance` (64: bases this close share one Under-you network) and `dig.networkMaxPerWorld` (6 networks in use), `ending_d.climbRadius` (40) and `ending_d.climbTimeoutSeconds` (900).
