# a1.0.16_02: Architecture

Contracts and ownership. Every worker reads this file and then only the DESIGN.md sections named in its prompt. The orchestrator is the only one who changes `core`. If you need something here changed, say so in your report. Javadoc on the `core` classes is the detailed reference.

## Build
- MC 26.3, Java 25, Loom 1.18-SNAPSHOT, loader 0.19.5, Fabric API 0.162.0+26.3. These come from the official template. Do not change them.
- The Gradle daemon runs on JDK 25 (`gradle/gradle-daemon-jvm.properties`, Homebrew `openjdk@25`).
- Build: `./gradlew build`. It also runs the game tests (`check` depends on `runGameTest`).
- Game tests only: `./gradlew runGameTest`. Headless server; the exit code is the number of failed required tests (non-zero fails the build). JUnit report: `build/gametest-report.xml`.
- Dev client: `./gradlew runDevClient` ("Dev Client"). Opens the singleplayer world `run/saves/a1016_dev`, creating it on first launch: creative, cheats on, user `Dev`, seed `-4180345853331630785` (spawn in a Dappled Forest; cold ocean and snowy slopes ~90 blocks, frozen peaks ~100). Delete the folder to start over. Plain `./gradlew runClient` still works.
- Server: `./gradlew runServer` (dir `run/`; it needs `run/eula.txt` with `eula=true`, which only Mariano accepts). The console takes commands on stdin, e.g. `a1016 state`, then `stop`, once the server says `Done`. Lines piped in at once (`printf '...\nstop\n' | ./gradlew runServer`) are read while it is still starting, and every one of them, vanilla `stop` included, answers "An unexpected error occurred": vanilla makes each console line's source as it reads it, and before any level exists that source has none, so `Commands.executeCommandInContext` fails on it before any command runs. Not the mod's (`DebugGameTests.consoleLinesReadBeforeTheWorldLoadsFailInVanillaToo`); wait for `Done`, or feed lines later.

## Code guardrails (the reviewer checks every one)
1. Every block, item or light change that "he" makes goes through `TraceService`. Every mob manipulation goes through `MobTamper`. The only exemptions are worldgen features and structures, which place blocks during chunk generation where nobody can see them, and D-047 (see TraceService).
2. Never damage, target or touch the player. Never spawn a mob. The figure entity (owned by entity) is the only entity the mod spawns. Fake sightings use mobs that already exist.
3. Nothing changes in the player's view: use `TraceService.isOutOfView`. The only in-view changes: the figure's dig-under (D-030), the fall after `removeLettingFall` (D-038), and Ending D's last minute giving back (`restoreVisibly`/`regrowVisibly`, D-048).
4. All timings come from `Pacing` or your config section. No hardcoded faster timings. `devFastMode` defaults to false.
5. In-game text never names real people, companies or forums. Use only "the developer", "the studio", "the team".
6. Fragment text matches DESIGN.md word for word.
7. Every accident is deniable and leaves exactly one clue.

### HerobrineState (`HerobrineState.get(server)`, file `data/a1016_02/state.dat`)
One per world: one shared story (D-058) with personal records per player (D-061). Change it only through its methods, which mark it dirty. The first `get` rolls the profile with a new random salt.
- `stage()`: `Stage` {ALONE 0, TRACES 1, PROXIMITY 2, TELLING 3, REMOVAL 4}. `setStage(server, stage)` fires `STAGE_CHANGED`.
- `attention()`: double, 0 to 100, one value for the world. `tension(UUID)`: that player's director tension, 0 to 100 (D-059); 0 for someone unknown. Both clamped; change them only through `Attention`.
- `profile()`: `WorldProfile`; `reroll(seed, salt)`. The salt is hidden (package-private). `worldgenSalt()`: derived from it once, then fixed for the world (a reroll keeps it); read it at server start for worldgen hashing.
- Known players: everyone who has ever been a participant, in first-join order. `List<Subject> players()`, `Optional<Subject> player(UUID)` (a known player's record `Subject(uuid, name)`, the name as of their latest join). Core records a player once they take part (a spectator who never plays is never known). Each known player has their own first blocks, play ticks (`GameClock.playTicks(server, uuid)`) and tension; someone who first takes part later starts with empty records and zero play ticks, never anyone else's. Tests and debug only: `addKnownPlayer(uuid, name[, FirstBlocks])` makes a known player of a private state (at the end of the join order, zero play ticks; each first block only where that slot is empty; someone already known only takes the new name). Game code never calls it.
- Owners (D-061): `Optional<UUID> owner(key)`, `owners()`, `clearOwner(key)` (debug and tests only). Choose through `PlayerWatch.ownerFor` (migrations: `adoptOwner`). `hasPlacedBlock(uuid)` (the player has a first block) is the one rule for who may become `story:first_blocks`: lore, world and the ending all pass `state::hasPlacedBlock`.
- `stopFired / listRead / tellingStarted` with setters. `tellingCount()` + `incrementTellingCount()` (lore counts every telling, D-039; the increment keeps the flag `lore:telling_count=<n>` in sync for older readers). `fragmentsRead()` (read by anyone: story fragments and the clues past F30) + `markFragmentRead(id)`. `fragmentsPlaced()` + `setFragmentPlaced(id, GlobalPos|null)`.
- Marked deaths, one shared list that records whose each death was (D-063): `markedDeaths()` (everyone's, oldest first), `markedDeaths(UUID)` (that player's), `addMarkedDeath(UUID player, MarkedDeath(cause, GlobalPos, day))` (stores it as that player's; `MarkedDeath` has a fourth field `player`, null only before it is added).
- `firstBlocks(UUID)`: that player's `FirstBlocks(block, craftingTable, chest)`, each a `PlacedBlock(GlobalPos, BlockState)` or null; `FirstBlocks.NONE` for someone unknown. Recorded by `PlayerWatch` from each participant's own placements.
- Old saves (D-062.8): a v1.0 `state.dat` (top-level `subject`, `firstBlocks`, `tension`, and the subject's ticks in `clock.playTicks`) loads as one known player with those first blocks, that tension and those play ticks; its marked deaths become that player's, and, if they placed a block, they adopt `V1_OWNER_KEYS` (`story:first_blocks`, `ending:home`): the story so far was theirs, so a friend who is online alone first never takes it over. The new format stores `players` (each with `uuid`, `name`, `firstBlocks`, `playTicks`, `tension`) and `owners`, and never writes the old fields.
- `effects()`: `Effects(musicOff, duskFogLevel)`. Change through `ClientEffects`; sent again on every join.
- `flags()`, `hasFlag(f)`, `setFlag(f, bool)`: free namespaced flags (`"lore:f04_done"`). Use them instead of asking for a new field. Shared ones: `ending:last_sighting` (set by ending: Ending A's last sighting may happen), `entity:last_sighting_seen` (set by entity: that figure was seen and is gone), `lore:still_burning` (set by world when its one still-burning camp is built, D-004; lore then puts F21 in that camp's emptied house only), `ending:path=<A|B|C|D>`, `ending:ended` (the story is over) and `ending:d_complete` (set by ending; the house copy stops for good after either of the last two), `ending:line_finished=<uuid>` (set by ending, one per player: that player's line was finished, by a hardcore marked death (D-063: they stay a spectator, and the story ends only once nobody online is left in it) or by Ending B's final death inside the copy; F10's "* removed" lines name exactly these, in order), `ending:d_step=<n>` and `ending:d_step_day=<day>` (set by ending on every advance of Ending D's chain: the step, 1 to 9, and the in-game day, on the world clock, it was reached; step 1's day is when F23 was first read; lore's late clues F38 to F44 read them, D-066), `ending:last_minute` (set by Ending D only while a real last minute gives back in view, D-048; never by the debug preview, cleared on reset and server stop; no sighting starts while it is set), `director:silence_forever` (set by the endings; while it or `ending:path=C` is set, no atmosphere fog surge or drift and the house copy waits), `director:obeyed_after_stop` (set by the director while OBEYED_AFTER_STOP has fired and nobody in the group told since, D-064; anyone's telling clears it at once; Ending A's obey rule), `entity:stared` (set by entity the first time anyone stares him down).

### Attention
`Attention.trigger(server, AttentionTrigger.X)` applies the configured weight of a Triggers row (`DISC_13_UNDERGROUND`, `NAMED_HIM`, `WROTE_NEAR_TRACES`, `ENTERED_TUNNEL`, `DUG_INTO_PYRAMID`, `REPLANTED_GROVE`, `CARRYING_LIST`, `RULES_BOOK_NEAR_BASE`, `LOW_RENDER_DISTANCE`, `SLEPT`, `STARED_AT_HIM`, `DESTROYED_OWN_WRITING`, `OBEYED_AFTER_STOP`, `AVOIDED_TRACES`, `LEFT_GROVES_ALONE`, `STOPPED_DISC_13`, `DAYLIGHT_OPEN_AREAS`, `LIST_IN_LAVA`). Also `raise/lower(server, amount, reason)` for attention (one value for the world: anyone's actions count, D-058) and `raiseTension/lowerTension(server, UUID player, amount, reason)` for that player's tension (nothing for someone who was never a participant). There is no world-level tension.

### WorldProfile (record)
`habits` (2 of `Habit` {CARVER, STRIPPER, WATCHER, MOURNER, COLLECTOR, VISITOR}), `density` {SPARSE, NORMAL, HEAVY}, `tempo` {EARLY, SLOW_BURN, VERY_LATE}, `fragments: Set<String>`, `signature` {STILL_BURNING, HOUSE_ELSEWHERE, CROSS_ROW}. `WorldProfile.roll(seed, salt)` is deterministic: `FIXED_FRAGMENTS` (11: D-003's ten plus F08, D-066) plus 11 to 13 of the other story fragments rolled, with `DEPENDENCIES` (D-003); every profile holds the fixed ones, so an old save gains F08. `storyFragmentIds()` is F01 to F30 (what a world rolls), `allFragmentIds()` those plus `CLUE_FRAGMENTS` (F35, F36, F38 to F44: the chamber plates, the team's note and the late clues), which are never rolled or listed in `fragments` but always enabled: `isEnabled(id)` is the question to ask (rolled, fixed or a clue). `tempo.paceFactor()` is 0.6 / 1.0 / 1.4. `hasStillBurning()` (D-004) and `hasHouseCopy()` (D-005) fold in F21 and F27.

### EventCard
```java

Tier tier();                  // AMBIENT, MINOR, MAJOR, SIGNATURE
Stage earliestStage();
Set<Habit> habits();          // weighting; empty = neutral

boolean hasFake();            // can fire as a false positive
```

Register cards in `init()` with `Director.register(card)` (stored in `CardRegistry`: `get(id)`, `all()`, `ids()`, `byTier(t)`), which works before the director is installed. When `fire` gets `NO_SPOT` (no out-of-view place exists right now), the director keeps the card for later. Sample: `debug_ping`.

### Director (`Services.director()`)
`tick(server)` runs every server tick; the impl picks its own cadence (`Pacing.directorTickTicks()`).
- A pacing per player (D-059). The director's memory (`data/a1016_02/director.dat`) is one world part (the stage clock on the world clock, the once-per-world signatures, the world's tag times, and the triggers that count once per occasion: SLEPT once a night however many sleep, disc 13 once per jukebox, daylight, AVOIDED_TRACES, and OBEYED_AFTER_STOP for the group, D-064) plus a pacing per known player by UUID (session and join grace, empty sessions, gaps and hard limits, their own first in-game day, major slot, tension's quiet, pity, decks with their holds and no-repeat cycles, history, low render distance once per session), each measured on that player's own clock. Every targetable participant decides on their own staggered cadence; sessions follow `PARTICIPATION`, per player. A v1.0 `director.dat` loads as the world part plus the first known player's pacing. Pacings are never pruned: the file grows by one small entry per player who ever took part (fine for co-op). The first-day rule counts from each player's own first participation, so on a world that got the mod mid-game majors wait one in-game day where v1.0 allowed them (intended).
- Felt moments (D-060.3). A card fires for the player whose pacing picked it, and only if every other targetable participant within `sharedMomentRadius` of them (the sharers) could have had it on their own (every gate of theirs open, the card new to them). It then counts as felt by each sharer: their gaps and hard limits, major slot, Alone cap, sightings per day, no-repeat cycle, tension and the quiet it may start, but not their own draws or fire counts. Together, the ambient and minor odds are split between them; a draw never picks a card a sharer already had, and such cards count as spent for the run-out rule, so a deck whose only undrawn cards a friend had refills at once when that gives back a card new to everyone there (otherwise the cycle is kept), and a used-up deck refills by the solo rule, so the pair's decks turn over together and never deadlock; a card held from before a friend who already had it came close goes back into the deck at once. Sessions share one mood: one started next to someone takes that session's mood (empty or not), and when sessions that started apart meet, every later one takes the earliest one's mood (`Recorder.sessionMood`, the sim's `MOOD` event), so a friend's empty session rolled far away never silences the other for its whole length. A friend's quiet still holds the shared moment (anything that fired would reach them). Alone, everything is the solo pace exactly (the solo 20 h sims are byte-identical to v1.0's).
- `FireResult fire(server, ServerPlayer player, cardId, fake)` is for debug: it fires for that player, skips gates and pacing but never the out-of-view rule; `SKIPPED` if the card is unknown or the player is not targetable (`PlayerWatch.isTargetable`: not a participant, or dead). A forced fire goes into the target's history, deck and tag times, never their gaps, tension or quiet, and the same for each sharer. Every fire is for a player: `/a1016 fire` from the console takes the first participant (D-062.9).
- `List<String> timewarp(server, days)`: every clock moves (`GameClock.warp`), then what time alone does (stages, each player's tension decay and quiet running out); the summary lines are a dry run of the first participant's pacing (else the first known player's, else a fresh one). `/a1016 timewarp <days>` and `/a1016 director timewarp <days> [player]` print them.
- `ticksSinceTag(server, CardTag)` is the world's answer: world-clock ticks since a card with the tag fired for anyone (`Long.MAX_VALUE` if never), for what the whole story waits on (the endings' accident gap). `ticksSinceTag(server, UUID, CardTag)` is that player's: their own clock since one fired for them or reached them as felt; a gap that is pacing asks this one (atmosphere's mining-in-the-dark sound gap). `inQuiet(server)`: any participant is in a forced quiet of their own (the conservative answer for one flag); `inQuiet(server, UUID)`: that player is. The per-player forms are interface defaults that give the world's answer (the stub), real on the director.
- `List<String> debugLines(server)` for `/a1016 state`: the world part, then each participant's own pacing. The stub's `fire` calls the card directly (and fires `CARD_FIRED`); its `timewarp` calls `GameClock.warp`. Dry runs (`DirectorSim`; `runGroup` for several players, where the world clock and the stage stand still while nobody is seated) reach Telling only when someone names him at a set hour (`simTellingAtHour`, `/a1016 director sim <h> telling <atHour>`); the director never enters it alone (D-041).

### TraceService (`Services.traces()`, real)
- `isOutOfView(ServerLevel, BlockPos | AABB | Collection<BlockPos>)`: false if any player is within 3 blocks of it, or has line of sight inside a 160° cone within the server view distance. Only opaque full blocks (`isSolidRender`) block sight; glass, leaves, ice and doors do not. The collection form checks every block with a see-through neighbour. Unloaded points count as unseen. D-027: the 3-block rule skips a block strictly below a player's feet, in the columns their hitbox overlaps, while they look 30°+ up and it is outside the cone. Geometry for tests: `static isOutOfView(level, box, viewers, near, cone)`, `positionsOutOfView(level, positions, viewers, near, cone)`, `Viewer.of(player, chunks)`.
- `remove(level, pos, cause)` (keeps a waterlogged block's water), `move(level, from, to, cause)` (block entity data moves too; `to` must be replaceable), `convert(level, pos, newState, cause)`, `leave(level, pos, state, [blockEntityData,] cause)` (only into air, replaceable plants, snow layer or fluid without a block entity; `saveCustomOnly` data such as chest items or sign text; never undone), `removeStack(level, pos, slot, count, cause)` (false if `count <= 0` or the slot is empty), `moveStack(level, from, slot, to, cause)`, `leaveStack(level, containerPos, stack, cause)` (first empty slot; never undone).
- `removeLettingFall(level, pos, cause)`: removes the block and lets the sand or gravel column on it, or the stalactite under it, fall by the game's rules. Only the removed block (and its own dependents) must be out of view; the fall and landing may be seen (D-038). Vetoes cover every cell. Only the removed block is ledgered. Refused if sand or gravel would break into an item.
- Taking back: `restoreBlock(level, removeEntry, toPos)` (its spot or up to 2 blocks off; the entry is closed, or rewritten as a MOVE), `restoreStack(level, removeStackEntry, containerPos)` (closes the entry), `equipFromLedger(level, stackEntry, mob, slot, cause)` (a REMOVE_STACK stack, or a MOVE_STACK stack taken back out of its chest, into a mob's empty slot; guaranteed drop, undamaged; the entry becomes EQUIP). All out of view; none creates items.
- `undo(level, entry[, cause])` takes one ledger entry back exactly once, out of view (REMOVE/REMOVE_STACK through the restores, MOVE/CONVERT/MOVE_STACK/sign text by the reverse edit; both entries closed). `UndoResult` DONE, IN_VIEW, UNLOADED (never loads a chunk) or BLOCKED (taken or built over, worn by a mob). Which entries to undo is the caller's choice (Ending D's `Undo.skipReason`).
- D-048, ending-only: `restoreVisibly(level, removeEntry, cause)` (its own spot, entry closed) and `regrowVisibly(level, leaves, cause)` (leaves into air, not ledgered) work in view, but only while `TraceService.LAST_MINUTE_FLAG` (`ending:last_minute`) is set, never into a cell a player or mob stands in.
- `editSign(level, pos, frontLines, backLines, cause)`: null or empty blanks a side; ledgered as BLOCK_ENTITY with the old text; waxed signs only for causes starting `lore:left/F30`.
- `startFigureDig(level, column, cause)` then `figureDig(level, dig, pos)`, `figureDug(level, dig)`, `figureFill(level, dig, entry, pos)`: ONLY for the figure's dig-under exit (D-030), allowed in view, within 3 blocks of the dig's column. Dig refuses fluids, bedrock, block entities and player-placed blocks; fill puts back one of that dig's own entries in its recorded state (ledgered as a MOVE).
- `addVeto(TraceVeto)`: `vetoes(level, pos, cause)` is asked for every position every edit would change (dependents, falls, containers, signs, figure edits included), with the edit's cause; one true refuses the edit. Keep it cheap. The cause is the ledger cause, except `GIVE_BACK_CAUSE` (`core:give_back`) for `restoreBlock`, `restoreStack` and so the REMOVE and REMOVE_STACK undos (giving back is never a cut). A veto that only knows `vetoes(level, pos)` (the default the three-argument form calls) answers for every cause. Lore's two: F30's twin signs (`UnbreakableSigns`), and Ending D's chamber (`TeamChamber.VETO`, F25 "the only place he cant cut": no edit inside the chamber's box unless it is left by others (`:left/`), the ending's own (`ending:`) or a give-back).
- Edits are silent: no drops, particles, sounds or spilled containers. Neighbours that would break (torches, signs, plants, rails, door halves) are removed silently and ledgered as `<cause>/dependent`; neighbours that only change shape are view-checked too. A falling block left without support, or an item frame, painting or leash knot on a changed block, refuses the edit.
- `batch(level, cause)` returns a `TraceBatch`: `.remove(pos) .move(a, b) .convert(pos, s) .leave(pos, s)` then `commit()`: one plan, one view check over every affected block, all or nothing (retry later if it returns false).
- Every edit returns false and changes nothing if anything it changes is in view. Tests and debug use `Services.traces().forced()`.
- Everything except `leave` and `leaveStack` goes to `TraceLedger.get(server)` (`data/a1016_02/traces.dat`): `entries()` oldest first (kind REMOVE, MOVE, CONVERT, REMOVE_STACK, MOVE_STACK, BLOCK_ENTITY or EQUIP; cause, day, pos, to, old state, block entity, stack, slots, entity), `remove(entry)` once undone. Causes are `<ws>:<what>`; any cause containing `:left/` (`lore:left/F07`, the team's stair `lore:left/ending-d/stair`, `world:left/...`) is what others left: `TraceLedger.isLeftByOthers(cause)`, never his trace for lore, never undone by Ending D.
- D-047, the only exceptions to "every change goes through TraceService": the F10 and F23 list books update their page text when opened or read (not ledgered; Ending D keeps every cause), and lore puts an invisible custom-data marker on the player's own written books to remember what they wrote. D-049 adds Ending D's markers on items (the cairn's first block, grove planks).

### PlayerWatch (`Services.watch()`, real)
Everyone takes part in the one story (D-058): a participant is an online player who is not a spectator. A dead player on the death screen still takes part (a death does not flap sessions or clocks); a hardcore death makes them a spectator, and then they stop.
- `List<ServerPlayer> participants(server)`: every participant, in first-join order (the order they first took part in this world; anyone not recorded yet comes after, by UUID). A new list each call.
- `isParticipant(player)`: this very object is online (a stale object from before a respawn is not) and not a spectator. `isTargetable(player)`: a participant who is alive and not removed, "may something happen to this player right now". Spectators are never targeted (D-062.7) but still count as viewers for every out-of-view rule.
- `Optional<ServerPlayer> participant(server, UUID)`: a fresh lookup, empty when offline or not a participant. D-062.1: keep UUIDs, never `ServerPlayer` objects across ticks or events; look the player up again and skip quietly if it comes back empty.
- `List<ServerPlayer> sharingWith(target)` (D-060): the target first (even if not a participant or not targetable), then every other targetable participant in the target's level within `Pacing.sharedMomentRadius` blocks of them, in join order.
- Stored owners (D-061): `Optional<UUID> owner(server, key)` is the stored choice; `Optional<UUID> ownerFor(server, key)` returns it, or if none is stored chooses now among the online participants (most play ticks of their own, ties to the earliest first join), stores it and returns it; empty, storing nothing, when nobody takes part. `ownerFor(server, key, Predicate<UUID> eligible)` chooses only among the participants `eligible` accepts (empty, storing nothing, while none is); a stored choice is returned as it is, whatever the predicate says now. `adoptOwner(server, key, uuid)` is for migrations: it stores a known player only where nothing is stored yet, online or not, and never replaces a choice (returns the stored owner; empty for someone who never took part). Choices persist and never flip. Keys are `"<ws>:<what>"`. Shared keys: `story:first_blocks` (`LoreApi.FIRST_BLOCKS_OWNER`, `EndingApi.FIRST_BLOCKS_OWNER`, `world.Bases.STORY_OWNER`: whose first crafting table, chest and block the story uses, and whose base the story's "near your base" fragments measure from, remembered while they are away: lore's F13 cairn and F10, ending D's cairn block and his cross, `MissingFirstBlockCard`, world's still-burning F21 camp; whoever needs it first chooses it, always with `state::hasPlacedBlock`), `world:house_copy` (`HouseCopyApi.OWNER_KEY`, `EndingApi.HOUSE_COPY_OWNER`: whose house the copy copies: world chooses it when the copy starts, among the participants whose first shelter in the overworld can be captured, never in a card's context check; a copy from before multiplayer adopts its first known player at once; F27 follows it) and `ending:home` (`EndingApi.HOME_OWNER`: whose base is "your house" for the group: Ending C's house taken apart, and Ending B's house when there is no house copy; the ending chooses it among the participants who have a base, and while its owner is away anyone's bigger house far from it becomes the home). A v1.0 save's subject adopts `story:first_blocks` and `ending:home` (`HerobrineState.V1_OWNER_KEYS`). Any other key is `<ws>:<what>` in its own workstream.
- Per player: `stillTicks(player)` (position only), `ticksSinceCombat(player)`, `ticksSinceJoin(player)`, `isSleeping(player)`, `Optional<GlobalPos> base(player)` (respawn point, else that player's own first block).
- `lastVisitDay(level, ChunkPos)`: the day a participant was last there (-1 if never; sampled every 5 s, 3x3 chunks; spectators do not count). Footprint (all players, capped per dimension): `wasPlacedByPlayer(level, pos)`, `wasDugByPlayer(level, pos)`, `placedNear(level, center, radius, Block | TagKey<Block> | Predicate<BlockState>)` and `dugNear(level, center, radius)` return `List<BlockPos>`. Placement comes from core's `BlockItemMixin`; a participant's placement also records their own first block, crafting table and chest.
- Sessions: listen to `HerobrineEvents.PARTICIPATION` instead of Fabric's JOIN and DISCONNECT.

### GameClock
Clocks (D-007, D-059). `playTicks(server)` is the world clock: it advances by 1 each server tick while at least one participant is online, plus timewarp; stages move on it. `playTicks(server, ServerPlayer)` and `playTicks(server, UUID)` are that player's own clock: ticks while they were a participant, plus timewarp since they first took part; 0 for someone unknown; per-player pacing is measured on it. `day(server)` is overworld clock time / 24000 plus timewarp days (day 0 is the first). `dayTicks(server)` is `day * 24000` plus the time of day. `warp(server, days)` adds the days, and 24000 play ticks per day to the world clock and to every known player's clock.

### MobTamper / FragmentService / AccidentPlanner / DeathMarker (interfaces)
- MobTamper (atmosphere installs it): `boolean freeze(mob, ticks)`, `face(mob, Vec3, ticks)`, `silence(mob, ticks)`, `moveOutOfView(mob, BlockPos)`, `void release(mob)`, `isTampered(mob)` (any effect on it now), and `bind(mob, UUID player)` (a default, a no-op in the stub): ties what is held on the mob right now to the player it is for, so it is released the moment they leave, die, turn spectator or change dimension, not only when its time runs out (D-062.5; call it right after the freeze, face or silence; the latest bind wins). Atmosphere's cards and entity's false positives (the cow or zombie held facing its player) bind; an unbound effect only expires. A `moveOutOfView` holds nothing, so accident's moved mobs have nothing to bind (and a moved mob stays where it was put for whoever comes, like any armed trap).
- FragmentService: `isEnabled(server, id)` (the profile's `isEnabled`: a rolled or fixed story fragment, or a clue past F30; the stub asks the same), `place(id, level, hint)`, `markRead(player, id)`, `Optional<GlobalPos> placed(server, id)`.
- AccidentPlanner, one armed trap per player (D-059): `Optional<TrapType> armed()` (whether any trap is armed: the newest, anyone's), `armed(UUID)` (that player's), `arm(player, TrapType)`, `arm(player, TrapType, BlockPos center)` (spots looked for around the center, nearest first), `disarm()` (every trap: the endings stop them all), `disarm(UUID)` (that player's only), `causedBy(player, DamageSource)` (any armed trap: a trap kills whoever sets it off). `TrapType(String id)` is a record, so accident defines its own. Accident's planner: each player's trap goes on their own routes, base and level, at most `maxTrapsPerSession` (1) per session of theirs; a new trap stays `trapSpacingBlocks` (48, the shared moment radius) from every other armed trap and its zone never overlaps theirs; the death, cross and cause are the victim's; a trap that just killed still claims a friend's death for `spentGraceSeconds` (10 s of game time: one accident, two marked deaths); traps stay armed and deniable when their player leaves, except the personal bed trap (only its own player's death counts; dropped when they turn spectator). `AccidentPlannerImpl.armedTraps(server)` maps every armed trap by its player (the dev overlay shows the viewer's own and the others' count).
- DeathMarker: `mark(player, cause, pos)` (records the death as that player's, builds their cross once the spot is out of view, fires the event), `count(server)` (everyone's), `count(server, UUID)` (that player's own, D-063; a default computed from the state), `lastCrossPos(server)` (the post bottom of the newest cross built for a marked death), `crossFor(server, death)` (the cross built for the death at exactly that spot, once it stands: any of the recent crosses, the last 64, not only the newest; two deaths on one block answer with the newer one's; Ending A's sign goes there).

### Events (`core.HerobrineEvents`, Fabric `Event`)
`STAGE_CHANGED(server, old, new)`, `TELLING(player, text, pos, namesHim)` (fired by lore), `FRAGMENT_READ(player, id)`, `MARKED_DEATH(player, cause, pos)`, `CARD_FIRED(player, cardId, fake)`. `PARTICIPATION(server, UUID player, participating)` (fired by core): exactly once per change, `true` when a player joins as a non-spectator or leaves spectator mode, `false` when they disconnect while a participant or become a spectator; never for a spectator who joins and leaves, never on server stop; a death or an ordinary respawn changes nothing (a hardcore respawn as a spectator is a stop). It fires after core's bookkeeping, at the end of the tick for starts (the player is a known player and `participant(server, uuid)` finds them) and from Fabric's DISCONNECT for a leave. Use it for sessions instead of Fabric's JOIN and DISCONNECT. Entity's own: `FigureApi.STARED(player, him)` when STARED_AT_HIM fires: once for each player who stares him down during a sighting (anyone's stare counts, D-060.4; never twice for one player in one sighting). Ending C counts it as staring into the fog.

### ClientEffects (payloads in core; atmosphere does the client side)
Payloads `FogSurge(strength, rampTicks, holdTicks, fadeTicks)`, `Silence(ticks, fadeTicks)`, `MusicOff(off)`, `DuskFog(level)`, `Sync(musicOff, duskFogLevel)`. Server: `List<ServerPlayer> fogSurgeShared(target, strength, ramp, hold, fade)` and `silenceShared(target, ticks, fade)` send the same payload, at the same moment, to `PlayerWatch.sharingWith(target)` and return who it went to, target first (D-060: use these for anything he does; keep per-player bookkeeping for each returned player). `fogSurge(player, ...)` and `silence(player, ticks, fade)` are for one player only. `setMusicOff(server, off)` and `setDuskFog(server, level)` are stored and sent to everyone online; `sync(player)` sends both on every join, spectators included. Client: atmosphere calls `core.client.ClientEffectsClient.install(handler)` with a `ClientEffectsClient.Handler`; callbacks run on the client thread.

Sounds (`SoundCues`, packets only, nothing in the world reacts): `List<ServerPlayer> playAt(ServerLevel, Holder<SoundEvent> | SoundEvent, SoundSource, Vec3 pos, volume, pitch)` plays to every player in that level within vanilla hearing range of `pos` (`max(volume, 1) * 16` blocks), spectators included, all with the same seed so everyone hears the same variant (D-060: use it for any sound he makes); returns who heard it. `List<ServerPlayer> hearers(level, candidates, pos, volume)` is that range rule over any players, in their order (tests and recording sound sinks hear with exactly it). `playTo(player, sound, [source,] pos, vol, pitch)` is for the rare sound only one player may hear.

### Config (`config/a1016_02.json`)
`ModConfig.pacing()` is `Pacing`: every number from DESIGN.md "The director", 4b, Triggers and related rules, in natural units, plus `...Ticks()` accessors (and `TickRange tracesStart(tempo)` etc.) that divide by `devFastDivisor` when `devFastMode` is true (default false). Use `ModConfig.realTicks(seconds)` for your own real-time values; cost cadences and chunk-load timeouts are plain ticks, named and commented. Multiplayer: `sharedMomentRadius` (blocks, default 48): participants this close to the target, in the same dimension, share its fog surges, silences and fired cards (D-060). Workstream tunables: `ModConfig.section("<ws>", Type.class, Type::new)` (public fields, no-arg constructor), stored under `sections.<ws>`. Multiplayer fields there: `world.newScarWorldGapDays` (1: at most one real new scar per in-game day in the whole world), `world.houseCopyBaseClearance` and `world.stillBurningBaseClearance` (64 blocks from every known base), `dig.networkShareDistance` (64: bases this close share one Under-you network) and `dig.networkMaxPerWorld` (6 networks in use), `ending_d.climbRadius` (40) and `ending_d.climbTimeoutSeconds` (900).
