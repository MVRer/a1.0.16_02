# Decisions

Creative and design decisions the orchestrator made where DESIGN.md is silent or ambiguous. Items marked **NEEDS MARIANO** wait for his answer. Until he answers, the default stands.

| ID | Decision | Why |
| --- | --- | --- |
| D-001 | We use the official Fabric 26.3 template that was already in the folder (Loom 1.18-SNAPSHOT, loader 0.19.5, Fabric API 0.162.0+26.3, Java 25) instead of generating it again. The existing `HimEntity` prototype and its textures become the entity workstream's starting point. | It already builds, and its versions are the template's. |
| D-002 | Singleplayer first. There is one `HerobrineState` per world with one "subject" player, the first to join. Multiplayer is out of scope for v1. | DESIGN.md leaves multiplayer open. Singleplayer hardcore is the intended mode. Mariano can override. |
| D-003 | Fragment roll: 10 fragments always exist. They are the core set from DESIGN.md (F01, F03, F06, F10) plus the Ending D chain (F07, F13, F23, F25, F28, F30), so the true ending is always possible. About 12 of the other 20 are rolled. Dependencies come along with them: F16, F22 and F29 need F15, and F29 needs F21. F20 appears only on the Ending B path. F04 is an event after "Stop.", not a placed fragment. | DESIGN.md says "about 12 of 20" and "keep the path open on every route". Exactly 20 fragments are left once the 10 are fixed. |
| D-004 | Still burning happens at most once per world. If F21 is rolled, its furnace is that moment, whatever the signature is. | Keeps the "once per world" rule. |
| D-005 | If F27 is rolled, the copy of your house gets built once, after day 20, even when the signature is something else. It still happens at most once. | F27 needs the copy to exist. |
| D-006 | There is no timed fallback into Telling. A player who never tells about him stays in Proximity, where accidents still happen. Stage 4 is entered by the ending workstream. | "Telling: player-driven" and "there is no safe default". |
| D-007 | "Real play time" means server ticks while the subject is online. The integrated server pauses with the game menu, so paused time doesn't count. An "in-game day" is overworld day time / 24000, so sleeping moves it forward. | We need one clock everyone shares. |
| D-008 | The profile salt is random per world and made on the first load. Two worlds with the same seed get different profiles. `/a1016 profile reroll` makes a new salt. | "Never the same run." |
| D-009 | Old scars stay at least 300 blocks from world spawn by default (configurable). | Matches F01's 300 to 800 band. "Far from spawn." |
| D-010 | `devFastMode` divides every real-time pacing duration by `devFastDivisor` (default 60). It is only for tests and debug runs. | Lets us test pacing without hard-coding faster timings. |
| D-011 | Pacing rules are the defaults: director tick every 30 s, 1 in 3 fired events is fake, at least 15 real minutes between minor events, at most 1 major per real hour, nothing in the first 5 minutes after joining, no major in the first in-game day. Stage times are from 4b and are scaled by the tempo `paceFactor` (0.6 / 1.0 / 1.4, which is ±40%). | DESIGN.md 4b. |
| D-012 | The out-of-view rule: a target is in view if any player is within 3 blocks of it, or has line of sight to it within a 160° cone and within view distance. The cone is conservative because the server can't know the client's FOV (Quake Pro at 16:9 is about 137° horizontal). | Guardrail: nothing vanishes on camera. |
| D-013 | F06 usernames have to be checked against real players before release. **NEEDS MARIANO** (open question in DESIGN.md). | Guardrail 6. |
| D-014 | The attention weights for every Triggers row are initial guesses picked by the scaffold, kept in config and tuned in playtests. | DESIGN.md gives the direction of each trigger but no amounts. |
| D-015 | Lore is split into two tasks, fragments (v0.5) and then telling (v0.6), and they run one after the other. The WorldProfile roll moves from the director workstream into core. | Each matches its milestone episode and avoids two workers in one package. world and lore both need the roll from day one. |
| D-016 | Git worktrees live in `.claude/worktrees/` and are ignored by git. VS Code's Java import excludes `**/.claude/**` so the IDE doesn't load each worker's copy. | Keeps Mariano's main checkout and IDE clean. |
| D-017 | The real `MobTamper` implementation moves from accident to atmosphere (wave 1). Accident uses it later for "Moved mob". Triggers are split by who owns the trace: director gets sleeping, render distance, daylight, disc 13, quiet after Stop and avoiding traces. dig gets entering a 2x2 tunnel. world gets digging into a pyramid, replanting a grove and leaving groves alone. lore gets naming, writing near traces, the list, the F15 book, destroying writings and the list into lava. entity gets staring at him. | Atmosphere is the first consumer ("mobs acting wrong"). Without this it couldn't demo anything until v0.7. |
| D-018 | A workstream may add its own S2C payloads in its own package, with id `a1016_02:<ws>/<name>`. The core `ClientEffects` payloads stay the shared ones. | Avoids a core change for every client effect (for example compass drift). |
| D-019 | The first accident not before hour 6 is scaled by tempo like every other 4b number, so an EARLY world can arm its first trap at about 3.6 h. | 4b: "All numbers shift by up to 40% with the world's tempo roll." |
| D-020 | (Superseded by D-044.) The director's first 20 h sims ran at about 0.6 minors per hour in Proximity overall. | Rarity is the product. |
| D-021 | Merges follow episode order when branches are ready together: figure (v0.2), then world and dig (v0.3), then atmosphere (v0.4), then lore, telling and accidents. A ready branch waits instead of jumping ahead. | Each tag is one video episode, so it should show only that episode's feature. |
| D-022 | Fog drift strength is 0.45 to 0.7 (was 0.55 to 0.85). Dusk fog per stage stays 0.15 / 0.3 / 0.45 / 0.6 / 0.7. | Mariano's playtest: 0.85 too strong, 0.6 is enough, 0.7 at most. |
| D-023 | Eyes: BRIGHT is the default. The eyes are unshaded white that ignores darkness, emit no light, have no particles, and partly resist fog (`eyeFogResistance` 0.5). In daylight they look flat. At night in fog, two pale points show while the body fades. FLAT and GLOW stay as toggle options. This overrides DESIGN.md guardrail 3 ("no glow") on purpose; nothing actually glows or lights the area. | Mariano's call (2026-10-09): he should be noticeable in the fog at night. |
| D-024 | Fragment timing, where the table says nothing exact: F14 (spawn shaft) can appear from Stage 1. "Late" (F23 to F27) means Stage 2 or later with 6+ fragments read. F22 waits until F15 has been read. F30 waits until F07 and F28 are placed. | Conservative readings of "late" and of the pointer chain. Mariano can override. |
| D-025 | Fragment books carry no author name. F17 is followed by 3 blank pages ("rest blank"). Fragment data files are lowercase (`f01.json`) because Minecraft rejects uppercase resource paths. | Guardrail 2: every text is human but unattributed. |
| D-026 | If world hasn't recorded a site lore needs within 60 minutes (`ownBuildDelayMinutes`), lore builds a minimal site of its own, out of view. | Keeps every enabled fragment placeable on any seed. |
| D-027 | View-rule refinement: the 3-block "too close, counts as seen" rule doesn't apply to a block strictly below the player's feet while they look up (30°+ upward) and the block is outside the cone. | The grove lure ("while you're up placing the last leaves, the blocks under you go") is impossible otherwise. You can't see under your feet while looking at a canopy. |
| D-028 | Accidents (v0.7) wait for telling (v0.6) before merging, per D-021, even though the branch is ready. | Episode order. |
| D-029 | Sightings must actually be seen. He spawns at 45 to 70% of the visible fog distance (was the outer 10%); close is 24 to 36 blocks. He leaves after 10 blocks of real approach or within 18 blocks (was about 1 step), after 3 s of direct stare plus a 2 s stare back, and never before 3 s on screen. All of it is tunable live with `/a1016 entity tune`. | Mariano's playtest (2026-10-09): "the player will never really get to see him". |
| D-030 | New sighting exit, "goes under": when found at a distance, he may dig straight down where he stands, sink, cover the hole over himself with the same blocks, and be gone. It is silent with no particles. The covered patch is the clue (the top comes back as bare dirt). This is the one deliberate in-view change, allowed only for the figure's own body through `TraceService.figureDig/figureFill`. | Mariano's idea (2026-10-09). It ties the sightings to the 2x2 diggers and to "Under you". |
| D-031 | Every number shown to the player or in debug output is formatted with `Locale.ROOT`. | Mariano's system is Spanish, and "0,5" breaks copy-paste into commands. |
| D-032 | New accident, "the zombie has your sword": a weapon or armor stack he took from your chest earlier turns up days later on an existing zombie at night, equipped (`TraceService.equipFromLedger`, drop chance 1.0). It hits harder because it has your gear. Deniable, because vanilla zombies pick up loot. The clue is that it's yours. No mob is spawned or buffed. | Mariano wanted angry dogs or stronger zombies. This is the in-rules version, approved by Mariano (2026-10-09). |
| D-033 | Redstone torches are a rare sign: a live card places a single redstone torch, "left by others", deep in a cave the player explored and left, or at the dead end of one of his tunnels. Never near the base, at most 3 per world, at least 7 in-game days apart. Old-scar lone lights keep their redstone-torch variant. | Mariano asked for a few casual redstone torches. DESIGN.md treats them as an [ours] option, not a rule, so keep them very rare. |
| D-034 | He follows you out of the overworld, with two parts only. (1) Sightings: in the End, a white-eyed figure among the endermen at the render limit; in the Nether, a still figure among zombified piglins at the edge of the Nether fog. Same rules as overworld sightings (out of view at spawn, never in view on despawn, never in combat). (2) Accidents: one block of the player's own bridge over the End void or a Nether lava lake goes missing out of view, or an enderman is moved onto their 1-wide End bridge. Deniable, with one clue (a perfect 1x1 gap). No End fog, no portal changes, no buffed dragon, no netherrack or gold shrine (excluded fanon). | Mariano (2026-10-09): "I like the constant feeling of being followed". He picked these two of the four proposals. |
| D-035 | Sighting distance follows the fog the client actually renders: the client reports its fog end to the server. Normal variants spawn at 0.55 to 0.75 of it. `sighting_close` spawns at 0.35 to 0.50, clamped to 16 to 28 blocks (revised after the next playtest: "a little farther, too close even with fog"). The 24-block floor becomes `minDistance` 12 (tunable, never under 8). The flee distance scales with spawn distance. Out of view at spawn and never despawning in view stay absolute. | Mariano's playtest (2026-10-09): "the close distance is still too big, I can't see him in fog". This overrides DESIGN.md's "never closer than 24". |
| D-036 | When he leaves at a run, he is always slightly faster than the player: speed = max(base run, the chaser's speed × 1.1), capped at about 9 blocks/s, all tunable. The player never catches him on foot. | Mariano (2026-10-09). |
| D-037 | Close chase (future): if a player chases him and gets within 10 blocks (for example with elytra), he turns and runs straight AT the player, passes beside them without touching (he has no collision), and is gone the instant he leaves their field of view. It's silent, with no particles. A deliberate, rare exception to "he always leaves first", and never contact or damage. | Mariano (2026-10-09). Queued for the next entity task. |
| D-038 | `removeLettingFall` only requires the removed support block to be out of view. Falling gravel or a stalactite may be seen falling and shattering, because that is vanilla behavior once the support is gone. | Otherwise falling dripstone, where the stalactite lands on the player by design, could never fire. The guardrail is that nothing vanishes on camera, and the game following its own rules is the point. |
| D-039 | Telling details: chat counts as telling, with no cap. Place not found only takes surface structures. F23 shows the latest cause of each marked death. The telling count is exposed as `LoreApi.tellingCount` and the flag `lore:telling_count=<n>`. | Lore worker's choices within the design; Mariano can override. |
| D-040 | Spawn worktrees one at a time. Two simultaneous `isolation: worktree` spawns raced on git's worktree metadata and one failed. | Infrastructure lesson. |
| D-041 | "His traces" (for writing near them) are only what he removed or moved: 2x2 tunnels and cuts, ocean pyramids, bare groves, dead mountains, emptied houses, the Under-you network, crosses and the house copy, plus his ledgered edits. Huts, abandoned builds, panic towers, lone lights, the bedrock stair and lore's own builds were left by people. Only writing his NAME starts Stage 3. Writing near his traces raises attention and counts as telling, but doesn't change the stage. | DESIGN.md Triggers: naming "starts Stage 3"; writing near traces is "telling, like the forum posts". Prevents a sign near F01's hut jumping the player to Stage 3. |
| D-042 | "Inside a dead mountain" (for silence and no animals) means inside the site's horizontal bounds AND standing on ground that really is dead (the surface isn't grass or plants). World records the site as soon as any of its chunks generates. | Keeps the design's "edges end on a sharp line": living grass just below the dead line stays normal. |
| D-043 | `enderman_on_bridge` cannot leave a 1x1 gap. Its clue is that no enderman was within teleport reach (32 blocks) of the bridge, so it shouldn't have been there. | Accident worker's call, accepted. A rewatching viewer can check. |
| D-044 | Pacing after tuning (192 seeds): Proximity minors about 0.7 to 0.8/h overall (about 1.3/h while active), a major every 2.3 to 5.4 h depending on tempo, about 0.8 ambient/h in Traces, about 40-46% of Proximity quiet or empty. Defaults changed: emptySessionChance 0.2, tensionThreshold 70, pity 1 h / +0.25 / +1.0. A real bug where waiting out quiet periods pushed every later major back is fixed. | Lands at the low end of 4b's targets. Mariano's playtests decide from here. |
| D-045 | Ending B escalates inside the hard pacing limits: `director:pace_multiplier` shortens the typical gaps but never below 1 real hour between majors or 15 real minutes between minors. Out-of-range multipliers are clamped to 0.25 to 4. | 4b's hard limits are what keep it rare even at the climax. One major an hour is already a big escalation from one every 2 to 4 h. |
| D-046 | Every `runGameTest` starts from a fresh test world (`build/run/gameTest/world` is deleted first). | The red main on 2026-10-09 was a test reading leftovers from its own previous run. |
